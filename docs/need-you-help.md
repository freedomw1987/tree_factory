## Q1 — 錄音要不要搬到原生層？（D14）

**對應票**：M01-US-106（原生錄音層）、M01-US-107（缺口標記）、M01-US-108（WakeLock）、SPIKE-002b
**背景**：實測 Tauri iOS webview 一進背景就停止收音（35 秒錄音只解出 5.1 秒），
**鎖屏期間的音訊會永久缺失**。產品承諾是「開會時幫你記錄」，而會議中鎖屏是必然行為。

| 選項 | 內容 | 代價 |
| --- | --- | --- |
| ⭐ **C（最推薦）** | v1 先出「必須停留前景」版（WakeLock + 缺口明示），**同時**做原生票 | v1 使用者會看到「此段未錄到」；原生票要 0.5～1 天 |
| A | 直接做原生層才出 v1 | 工程風險全壓在最前面，其他 Module 順延 |
| B | 只做前景版，原生層永遠不做 | 產品核心承諾打折（開會不能鎖屏） |

**最推薦 C 的原因**：終點一定是 A（原生才是唯一解），但 C 讓 v1 至少**誠實地缺**
而不是「假裝有錄到」——後者是比缺錄更痛的失敗（使用者以為記下了，其實沒有）。
**暫定代答**：C（`docs/trust-log.md` 2026-10-08 05:05）
**抉擇**：- [x] ✅ 繼續做（C：v1 前景版 + 原生票同步做）
**抉擇理由（2026-10-08）**：用戶確認同意 trust mode 期間的暫定代答；接受 v1 缺口、並行做原生票。

## Q2 — 模型策略與成本（D15）

**對應票**：M02-US-219（分階段模型）、M03-US-319（成本看板）
**背景**：SPIKE-004 推估 2 小時會議成本 —— 全用 70b-fast 且無快取約 **US$0.48／場**；
即時逐字稿用 8b ＋會後筆記用 70b 約 **US$0.09／場**。免費額度（10,000 neurons/日）約**一天只能跑 1 場**。

| 選項 | 內容 | 代價 |
| --- | --- | --- |
| ⭐ **A（最推薦）** | 分階段：即時 8b / 會後 70b | 兩套模型設定與驗證；即時逐字稿品質略降（只影響「邊聽邊看」，不影響最終筆記）|
| B | 全部 70b（品質一致）| 約 5 倍成本（US$0.48/場），免費額度幾乎不可用 |
| C | 全部 8b（最便宜）| 會後筆記品質可能不足（這是產品價值所在）|

**最推薦 A 的原因**：即時階段的任務是「不漏字、給回饋」，8b 足夠；
真正的產品價值在會後筆記 → 錢花在那裡。成本差 5 倍但體驗差很小。
**暫定代答**：A（`docs/trust-log.md` 2026-10-08 05:35）
**抉擇**：- [x] ✅ 繼續做（A：分階段即時 8b / 會後 70b）
**抉擇理由（2026-10-08）**：用戶確認同意 trust mode 期間的暫定代答；接受 US$0.09/場 的成本；錢花在會後筆記。

## Q3 — 24k 上下文窗口：接受壓縮，還是換模型？

**對應票**：M02-US-218（壓縮政策）
**背景**：`llama-3.3-70b-fp8-fast` **只有 24,000 tokens** 上下文，而 2 小時逐字稿約 20k →
幾乎塞滿，加上系統提示與筆記必然溢出。**壓縮一定會發生**（不是選項）。

| 選項 | 內容 | 代價 |
| --- | --- | --- |
| ⭐ **A（最推薦）** | 顯式設定壓縮政策 + **逐字稿一律用工具從 `transcript_segment` 表檢索**（架構不變，理由變硬）| 要實測「壓縮後筆記仍完整」（M02-US-218）|
| B | 換更大窗口模型（Workers AI 上有更大的，如 Kimi 系列）| 單價高一個量級，成本模型要重算 |
| C | 分段落產筆記（每 20 分鐘產一次，最後合併）| 多一次模型呼叫＋合併邏輯，且跨段落的因果關係可能斷 |

**最推薦 A 的原因**：既有架構本來就是「M02 獨佔寫入、M03 的 `ask()` 是唯一檢索點」，
source of truth 在資料庫不在上下文 → 壓縮只影響對話記憶、不影響記錄完整性。
**這是架構紅利，不需要改設計**，只要把政策寫死並驗證。
**暫定代答**：A（`DESIGN.md` D15、`system-design.md` F23）
**抉擇**：- [x] ✅ 繼續做（A：壓縮政策 + 工具檢索）
**抉擇理由（2026-10-08）**：用戶確認同意 trust mode 期間的暫定代答；架構紅利不需改設計，只驗證「壓縮後筆記仍完整」。
