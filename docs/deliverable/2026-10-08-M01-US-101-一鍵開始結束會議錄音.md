## 1. 這次完成什麼

把「按一顆鈕就開始錄會議、再按一下結束」這條主線做成**可自動驗證**的完整切片：
前端外殼（Svelte 5，4 個畫面）＋ 伺服端權威時間軸（Durable Object 的 `ends_at`，
2 小時到點由 alarm 強制結束）＋ 真瀏覽器端到端測試（假麥克風 + 真 worker）。

**關鍵成果**：

- ✅ 前端外殼從 0 到有：`app/ui/` 4 個畫面、4 種狀態機（idle / recording / interrupted / limit_reached）
- ✅ 伺服端權威時間軸：`ends_at = started_at + 2h` 由 DO SQLite 的 CHECK 不變式把關，裝置端只負責顯示
- ✅ 25 分鐘提醒 / 到點自動結束走 **DO alarm**（最早者優先，且醒來後會補排到點 alarm，不會被餓死）
- ✅ 自動化驗收四層全綠：單元 35 + 126、M01 回歸 83 + 35、E2E 6 條、真 workerd 冒煙 31 項
- ✅ Gate 4 兩輪獨立稽核：第 1 輪 9 條（1 P0 / 2 P1 / 6 P2）全修，第 2 輪 0 P0 / 0 P1

### 1.2 為什麼做這個改動

- **問題／脈絡**：SPIKE-002 證實 Tauri iOS webview 的 `getUserMedia` 前景可用，
  但「可用」不等於「這條故事做完了」——麥克風權限、前景/背景切換、每秒 tick、跨來源 CORS，
  這些都是**接線**問題，單元測試一定驗不到。而且 2 小時上限若由裝置端自己算，
  使用者改個系統時間就能繞過，錄音長度就變成不可信。
- **為什麼選這個解法**：把時間權威放在伺服端（DO 的一列 SQLite + alarm），
  裝置端退化為純顯示；同時把核心邏輯（狀態轉移、上限計算）寫成**純函式**，
  才能用注入時鐘在毫秒級驗完 2 小時邊界，不必真的等兩小時。
  唯一沒選的是「先把 UI 做完再補 worker」——那會讓 E2E 永遠缺一半（沒有真 worker 就沒有真真相）。
- **成功怎麼看**：真瀏覽器（真 Chromium + 假麥克風 + 真 workerd）能把 6 條 BDD 走完，
  而且針改伺服端 DB 會被抓到；**走錯的樣子**是「E2E 只能用 mock 才綠」，
  那代表接線問題其實沒驗到。

### 2.4 改動背後的理由

| 改動 | 為什麼這樣設計 | 放棄的選項 |
| --- | --------------- | ----------- |
| 結束原因單一來源 `SESSION_ENDED_REASONS` | 第 1 輪稽核抓到的 P0 是「`aborted` 寫得進、讀不出」——型別、SQL CHECK、路由、讀取驗證四處各寫一份清單，必然漂移。改成一處定義、四處推導，這一類 bug 結構上不可能再發生 | 只補上漏掉的那一個字串（最小 diff，但同類錯誤下次還會發生） |
| 同一 meeting id 結束後再 `start` ＝有文件的 no-op | 裝置端每次 `crypto.randomUUID()` 都是新 id，所以「同 id 再 start」只會發生在異常重試；回 201 + `phase:"ended"` 讓重試是安全的，且不會讓已結束的會話復活 | 回 409（要改契約 + 前端行為，換來的是更吵的錯誤路徑） |
| `alarm()` 醒來後補排（`#rearmSessionAlarm`） | DO 的 alarm 是「單一 slot、最早者優先」；harness 的 alarm 比 2 小時更早時，會話的到點 alarm 會被吃掉。醒來時若仍在 recording 就重排 | 改成用兩個 DO 或 cron（超出本票範圍）；只在到期時處理（就是原本的 bug） |
| E2E 用假麥克風 + 真 worker（不用 mock） | 這條故事最容易壞的是接線，mock 掉 worker 就等於把要驗的東西驗掉了 | 只跑單元測試（快，但等於沒驗 CORS／權限／事件） |
| E2E 用 `page.route` 把 `endsAtMs` 壓成 3 秒 | 不可能在 E2E 等兩小時；真邊界由注入時鐘的單元測試證明，E2E 只驗「到點會進 limit_reached 且畫面說得清楚」 | 真的等兩小時（不可能）／只驗單元（接線就沒驗到） |
| 冒煙腳本 run id 化 | 原本寫死 meeting id，dirty state 重跑會紅 6 項——「只能跑一次」的探針等於沒有探針 | 每次跑前清 state（會掩蓋「同一份資料再訪」的情境） |
| 錯誤面**不**洩漏內部細節 | 阻斷頁只說「麥克風被拒 + 怎麼去設定打開」，不把 `NotAllowedError` 等原始碼給使用者 | 直接顯示原始錯誤（除錯方便，但使用者看不懂） |
