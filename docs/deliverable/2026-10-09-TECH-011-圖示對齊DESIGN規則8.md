## 1. 這次完成什麼

用戶一句話「避免用 emoji icon，請 DESIGN.md 加上，並在 APP 都更換為 SVG icon」。
查證後發現**規則早在 2026-10-07（DESIGN v2.2）就已立**、PRD 原型也改了 100+ 處，
**獨漏 app 實作**：`app/ui` 還有 5 處 emoji 當圖示，而且沒有任何測試會攔住它。
所以這次做兩件事：把 5 處換成 SVG，並把「會漏的守門」補成「會亮燈的守門」。

**關鍵成果**：

- ✅ `app/ui` 5 處 emoji 全數換成 `Icon` 元件（chat / mic / ban），圖形指令取自原型 `IP` 表逐字元相同
- ✅ 三層守門：全檔掃描（含 `.css`）＋ 原型同源比對（node 腳本）＋ vitest 元件規格 ＋ E2E 真實渲染
- ✅ `DESIGN.md` §3 的 8 處 emoji 改為 `Icon(name)` 寫法，§3 不再與 §5 規則 8 自相矛盾
- ✅ 正式建置 bundle 實測 **0 emoji**（`npm run build` 後掃 `dist/`）

### 1.2 為什麼做這個改動

- **問題/脈絡**：規則立了 2 天、原型改了 100+ 處，實作卻沒跟上，且**沒有任何自動防線**。
  這種「規則寫在文件裡、實作默默退化」的缺口，人眼複查一定會再漏。
- **為什麼選這個解法**：把圖形資料**從原型抽出**而不是手畫（同一份設計不能長出兩種圖示），
  並讓「同源」變成**可執行**的斷言（`scripts/check-design-icons.mjs` 逐字元比對）。
  守門刻意做成三層而不是一層：vitest 只看得到 `.svelte`/`.ts`/`index.html`（Vite `?raw` 讀 `.css` 回空字串），
  所以 `.css` 這條最陰的路（`content:"..."`）交給 node 腳本補。
- **成功怎麼看**：任何人把 emoji 塞進 `app/ui`（含 CSS、含測試檔）或改壞任一圖形，`npm test` / `npm run lint`
  會立刻失敗，並指出檔案與行號。**走錯的樣子**：規則只寫在文件、守門只存在於某人的記憶裡。

| `app/ui/src/lib/ui/emoji.ts` | 去註解與 emoji 偵測（逐字元掃描器；守門自己的邏輯） |

### 2.4 改動背後的理由

| 改動 | 為什麼這樣設計 | 放棄的選項 |
| --- | --------------- | ----------- |
| 圖形資料由腳本自原型抽出 | 原型是設計單一來源；手抄一定會漂移，且漂移沒有人會發現 | 手寫 path（快，但「同源」變成口號） |
| 新增 node 腳本掃 `.css` | Vite `?raw`/`?inline` 讀 `.css` 實測回空字串，vitest 結構上掃不到 CSS | 只改文件說明「掃不到 `.css`」（承認缺口＝留缺口）；加 `@types/node` 走 vitest（破壞專案「無 node types」約定） |
| 去註解改成逐字元掃描器 | 舊正則的寫法是「看到 `//` 就刪掉該行剩下的部分」，會把同一行 `//` 之後的**程式碼**當註解刪掉 → emoji 假通過 | 保留正則＋放寬掃描（等於放任假通過） |
| 守門連測試檔也掃（測試用碼位寫） | 規則最嚴＝`src/**` 任何 emoji 字面值都不行，不留例外給自己 | 排除 `*.test.ts`（留後門：emoji 躲進測試檔就永遠不會亮燈） |
| `iconShape()` 只認自有鍵 | `ICON_PATHS[name]` 對 `"toString"` 會沿 prototype chain 取值並被 `@html` 渲染（非 XSS 但不該發生） | 直接查表（現況）；`Object.create(null)`（改動大、收益相同） |
| 權限頁用 `ban` 而非 `mic_off` | 原型該畫面就是用 `ban`；同一份設計不該長出兩種圖示 | `mic_off`（語意更貼近，但與原型不同源） |
