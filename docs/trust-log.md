## 2026-10-09 01:27:00 +0800 — 規劃／設計（M01-US-102）

**問題**：US-102 的四個關鍵設計歧義要怎麼代答？
**決策（D-US102-1 分段方式）**：MediaRecorder **每 30 秒 stop/start**，讓每段是「獨立可解碼的檔」。
**理由**：`start(timeslice)` 吐的是同一容器的片段，無法單獨解碼／單獨回補；獨立檔才能
「上傳成功才刪」（AC-1）。代價是換段處 < 100ms 空隙，已知限制寫進交付文（另由 US-107 標缺口）。
**可推翻**：✅

**決策（D-US102-2 冪等鍵）**：冪等鍵 = 會議內單調遞增 `seq`；另存 `contentHash`（SHA-256 前 16 hex）
做**衝突偵測**：同 seq 不同 hash → 409 `SEQ_CONFLICT`，不覆蓋。
**理由**：seq 對應時間軸，能判斷「缺段」（AC-4 要連續性）；hash 防「同 seq 換內容」造成
音檔與逐字稿對不上。伺服端用 `INSERT OR IGNORE`（PK=seq）保證冪等是**原子**行為，不需讀改寫。
**可推翻**：✅

**決策（D-US102-3 本機佇列位置）**：IndexedDB（webview 持久、app 被殺仍在）；key=`${meetingId}:${seq}`。
「已 ack」以**伺服端 ledger 為權威**，本機標記只是快取，重開後用 `GET /audio/chunks` 對帳。
**理由**：若以本機標記為權威，本機與伺服端不一致時會永久漏段；對帳是唯一能自癒的做法。
**可推翻**：✅

**決策（D-US102-4 恢復流程）**：app 啟動掃 IndexedDB → 有未 ack 分段 → 顯示「有未完成的會議」
→ 使用者選續傳／丟棄（丟棄需二次確認）；**不得自動丟棄**（AC-3）。
**理由**：AC-3 原文要求「詢問是否續傳」。**可推翻**：✅

**決策（D-US102-5 逐字稿去重）**：`POST /transcript` 增加 `chunkSeq`；同 seq 重送回
`{accepted:false, duplicate:true}` 且不增加計數、不產生第二句。
**理由**：AC-4「無重複句」若只靠前端自律，重送音檔觸發 ASR 重跑時必然破功；必須伺服端幂等。
**可推翻**：✅

**決策（D-US102-6 音檔保留政策 / Q4 定案）**：伺服端分段音檔保留「會議結束後 7 天」或被使用者
刪除會議時即刪；本機分段在 ack 後**立即刪除**。
**理由**：隱私最小化（音檔是最敏感資料）+ 成本可控。**本票只落地政策與欄位**，實際清理排程掛
M02-US-204（不假裝已實作清理，交付文誠實記載）。**可推翻**：✅

## 2026-10-09 02:20:00 +0800 — M01-US-108（WakeLock 防關屏）設計與審查處置

**背景**：US-107 讓「斷了要誠實說」，US-108 讓「不要白白斷掉」——錄音期間用 `navigator.wakeLock("screen")` 壓住自動關屏。

**決策（D1 只在 `recording` 時持有）**：`interrupted` / `limit_reached` / `idle` 一律放掉 sentinel。
**理由**：中斷時畫面本來就寫「錄音已中斷」，這時還宣稱「已防止螢幕關閉」是雙重誤導；上限到了更不需要續航。**可推翻**：✅

**理由**：真機沒有第二個 `navigator.wakeLock` 可以試；把能力邊界做成介面，六態與競態就能用單元測試釘死（最終 22 條），E2E 才不必偽造整個瀏覽器。**可推翻**：✅

**理由**：規格上 WakeLock 在背景一定被收走，回前景不會自己回來；而「回前景但還沒續錄」若也重取，畫面就會宣稱有保護而其實沒在錄（本票最不能犯的錯）。**可推翻**：✅

### 決策 1（必修，不延期、不降級成已知限制）

Gate 4 第二輪 oracle 的 P1 是**語意等級**的：AC-6 寫「緩衝有界、一字不丟」，但第一版只擋**字數**，

逐字餵與逐批在聚段語意上等價（聚段器本來就逐字判斷切點），代價可忽略。

### 決策 3（已知邊界不擴大範圍）
