## 背景（為什麼要這一票）

2026-10-09 的 iPhone 12 mini 真機驗收，回報了**三個同家族**的「按不到」：狀態列蓋住
「開始會議」、Home Indicator 吃掉「長按結束會議」、逐字稿變長把結束按鈕推出畫面。
根因是同一個：**E2E 只跑 Desktop Chrome（高視窗、安全區恆為 0）**，桌機永遠不會發生這些事。

第一輪修好了「會議中」畫面，並補了 3 條 iPhone 尺寸的 E2E。剩下的三個畫面
（會議列表 / 開始 sheet / 權限阻斷頁）**從來沒在手機寬度被檢查過**；而**橫向**更是完全沒有處理——
`index.html` 只宣告了上下安全區，橫向時瀏海在左右，專案沒有任何水平留白。

## 目的

1. 把「手機寬度」的檢查從 1 個畫面擴到 4 個畫面（含橫向），並用**幾何斷言**而不是截圖目視。
2. 補上橫向安全區（左右）的讓開，讓橫向使用不會讓內容落在瀏海底下。

### 誠實的範圍界定（這一票**沒有**解決的事）

- **這是近似，不是真機。** 安全區數值是注入的常數（與已交付的 3 條同一手法）；
  `env()` 在真機由 WebKit 計算，橫向時左右安全區的實際值還取決於使用者的握持方向。
  **真機仍是最終驗收依據**；本票的價值是「同一個錯誤不會再無聲溜過」。
- **只驗幾何，不驗視覺。** 顏色、字級、對齊美感、動效都不在本票；也不引入截圖比對
  （產出這一票的 agent 看不到圖，截圖不能當斷言）。
- **只驗 4 個畫面、2 個尺寸。** iPad、iPhone SE、Android、動態字級（Dynamic Type）放大、
  鍵盤彈出時的 viewport 變化都不在範圍內。
- **權限阻斷頁是「瀏覽器層拒權」**：測試在頁面註冊 init script，讓 `getUserMedia()` 直接丟
  `NotAllowedError`（產品自己的錯誤映射把關），與 iOS 系統設定關閉麥克風的文案來源可能不同；
  本票驗版面，不驗文案。
- **E2E 驗不到「安全區變數有沒有被宣告」**：橫向那 3 條自己注入 `--safe-left`／`--safe-right`，
  所以把 `index.html` 的宣告整段刪掉它們**照樣全綠**（突變 M1）。那一格由原始碼不變式測試守
  （M1b／M4 會紅）；**兩層合起來才算守住**，不得用 E2E 綠燈宣稱宣告也守住了（設計 D7）。
- **真機橫向只會有一邊有瀏海**：對稱夾具（44／44）驗不到「左右顛倒」與「只讓開一邊」
  （Gate 4 oracle 實測兩者皆 `0 紅`），所以橫向三條各跑三組夾具；`AC-4` 的「安全區 left 44 / right 44」
  是**其中一組**，不是唯一一組。

## 刻意不做

| 不做 | 為什麼 |
| --- | --- |
| 加更多尺寸（SE / iPad / Android） | 尺寸越多越容易變成「為了讓某尺寸過關而放寬斷言」；等真的有第二台真機回報再加（設計 D2） |
| 用截圖比對做視覺回歸 | 需要人審圖與 baseline 維護；「按不到」是幾何問題，數字斷言就夠（設計 D8） |
| 為了讓斷言過關而降低 44px 門檻 | 44px 是專案既有 `--tap`/DESIGN §2.3；例外只能「移出白名單並說明理由」（設計 D4 / D7） |
| 順手重排（改間距、改字級、改斷點） | 這一票的觸發點是真機的「按不到」；順手改版會讓「哪一條斷言守住哪個修正」失去對應 |
