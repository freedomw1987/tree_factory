# M01-US-101 AC 範本

> 對應 Backlog: [M01-US-101 in docs/backlog.md](../backlog.md)
> Module: M01（聽：收音與即時逐字稿）
> 最後更新: 2026-10-08

## 背景

作為會議參與者，我想一鍵開始與結束會議錄音，以便我不需要思考技術細節就能把會議錄下來。

本 US 是 M01 的入口票，也是整個產品的第一個可驗證動作。AC-4 特別要求「被中斷時不得假裝仍在錄」，
因為一個騙人的錄音指示燈比沒有指示燈更糟——使用者會以為自己錄到了。

## Given / When / Then

- **Given** app 在前景且已取得麥克風權限
  **When** 使用者點「開始會議」
  **Then** 3 秒內進入「錄音中」狀態並顯示累計時間

- **Given** 正在錄音
  **When** 使用者結束會議
  **Then** 立即停止收音並保留本次 session 於本機
  **And** 不得刪除任何已產生的逐字稿或音檔

> **實作澄清（2026-10-08）**：DESIGN.md §4.1 決定 3 把結束動件訂為**長按填滿 1 秒**
> （避免會議中誤觸結束錄音），因此驗收時「結束」＝按住結束鈕 1 秒直到填滿，
> 而非單次點擊；按下未滿 1 秒即放開不得結束（E2E 已驗）。
>
> **本輪範圍邊界**：逐字稿**內容**的落盤屬 M01-US-102/103；本輪實作的是**寫入守門員**
> （`POST /transcript` 在到點/結束後回 409/400，不建立資料），以及「沒有刪任何東西」的反向斷言。

- **Given** 尚未取得麥克風權限
  **When** 使用者首次點「開始會議」
  **Then** 顯示為何需要麥克風的說明，並提供前往系統設定的入口
  **And** 不得靜默失敗（不可只把按鈕變灰而無說明）

- **Given** 正在錄音
  **When** app 被切換到背景或裝置鎖屏
  **Then** 畫面明確顯示「錄音已中斷」狀態
  **And** 不得繼續顯示錄音中的計時器

- **Given** 一場會議已進行 1 小時 55 分（距上限 ≤ 5 分鐘）
  **When** 畫面顯示剩餘時間
  **Then** 顯示黃橫幅明說「再 N 分鐘就到 2 小時上限，記錄會完整保留，可開新一場接續」
  **And** 此時紅燈仍亮（還在錄），不得提前熄滅

- **Given** 會議累計時間達到 2 小時上限（決策 D5）
  **When** 上限到達
  **Then** **自動結束錄音**、紅燈熄滅、計時器停止更新
  **And** 畫面明說「已達 2 小時上限」且「2:00 之後的內容不會被記錄」
  **And** 2:00 之前的逐字稿與音檔完整保留，並提供「產生記錄」與「開新一場」兩個出口
  **And** 不得延長、不得靜默截斷、不得繼續顯示錄音中（違反 P2 誠實原則）

> 對留著上一輪資料的 workerd 重跑會失敗（實測 6 項紅）。已改為每次執行帶 run id

它服務的是**現行**檔案（命中 1），但仍建議在 1420 空閒的乾淨環境再跑一次以完全排除疑慮。

## 真機驗收與「按不到」修復（2026-10-09）

用戶在 iPhone 12 mini 真機驗收時連續回報兩次「按不到」，加上他自己找到的替代路徑，
三個症狀其實是同一家族：**內容溢出 / 未讓開系統 UI → 按鈕落在可視範圍或手勢區之外**。

| # | 症狀（用戶原話）| 根因（實測）| 修法 | 守住它的測試 |
| --- | --- | --- | --- | --- |
| 1 | 「按不到開始會議 button」| `index.html` 有 `viewport-fit=cover`（內容延伸到系統 UI 底下），但樣式**只有底部** `env(safe-area-inset-bottom)`，**完全沒有頂部留白**；按鈕在 y=16~60，被約 50pt 的狀態列蓋住，點擊被 iOS「點狀態列回頂部」手勢吃掉 | `.shell` 加 `padding-top: var(--safe-top)` | 靜態不變式 + E2E 第 1 條（注入 50pt 後量按鈕 y）|
| 2 | 「結束會議 button 按不到」| `MeetingScreen` 的 `.meeting` 用 `min-height: 100dvh`，但它就在外框 `.shell` 內（外框已有頂部留白）→ 畫面比視窗再高 50px，最後的「長按結束會議」被推到 y=794~810，整顆落在 34pt 的 Home Indicator 手勢區 | `.meeting` 改 `flex: 1`（填滿外框，不自己拿視窗高度）| E2E 第 2 條 |
| 3 | 「原來是可以 scroll down」（用戶自己找到的替代路徑）| `.shell` 只有 `min-height: 100dvh` → **高度未定**，子元素的 `flex: 1`（`flex-basis: 0%`）無法解析而退回「依內容」→ 逐字稿一長就把畫面往下撐（實測按鈕底緣距畫面底 **-3066px**）| `.shell` 改 `height: 100dvh`、`.content { overflow-y: auto }`；逐字稿自己捲 → **結束按鈕永遠釘在底部、不需捲動** | E2E 第 3 條（灌 60 行假逐字稿）|

**測試先紅後綠（皆為真實重現，非事後補寫）**：

| 階段 | 指令 | 輸出 |
| --- | --- | --- |
| 紅 | `npx vitest run src/lib/layout/safe-area.test.ts` | `expected [ Array(1) ] to deeply equal []`（`MeetingScreen.svelte` 用了 `100dvh`）|
| 紅 | `npx playwright test e2e/iphone-viewport.spec.ts` | `按鈕底緣距畫面底只剩 32.0px；iOS 底部手勢區有 34pt` |
| 紅 | 同上（第 3 條，改動前） | `逐字稿被灌滿之後，按鈕底緣距畫面底剩 -3066.0px` |
| 綠 | `app/ui` 單元 | **54 passed / 5 files**（原 49/4；+5 條真機不變式）|
| 綠 | `npx svelte-check --threshold error` | **0 errors / 0 warnings** |
| 綠 | `REGRESSION_MODULE=M01 npm run regression` | **40 passed \| 14 skipped**（+2）|
| 綠 | `worker npm test` | **132 passed / 11 files** |
| 綠 | `npx playwright test`（全套） | **9 passed**（原 6，+3 條 iPhone 尺寸）|

**為什麼先前 6 條 E2E 全綠卻擋不住**：E2E 專案是 Desktop Chrome——沒有狀態列、沒有
Home Indicator（Chromium 的 `env(safe-area-inset-*)` 恆為 0），逐字稿也還沒有內容。
修法把安全區抽成 `--safe-top` / `--safe-bottom`（定義在 `index.html`），E2E 注入
iPhone 12 mini 的實測值（50 / 34）把真機版面搬進 CI。

> **陷阱記錄（vite）**：`import.meta.glob(..., { query: "?raw" })` 對 `.css` 會拿到**空字串**
> （空值會讓「安全區只能定義一次」這條規則假通過），所以變數定義放在 `index.html`，
> 由 `?raw` 讀得到。

**誠實聲明**：E2E 注入的是常數，不等同 WebKit 的 `env()` 實算；真機仍是唯一最終驗收依據。
這 3 條 E2E 的價值是「同一類錯誤不會再無聲溜過」，不是「取代真機」。

## 待辦（本輪不做，已明示）

> 下列項目已於 2026-10-08 §2.4 反省時轉成 Backlog 票（見 `docs/backlog.md` 的 TECH-006 ~ 009），
> 不留在對話裡。

1. **DB 竊改硬化**（→ **TECH-008**）：目前只驗「長度不變式」（`ends_at - started_at = 2h`）。若要把「同量平移」
   也擋下來，需要把「現在時間」餵進讀取驗證（`endsAtMs <= now + 2h`）並容忍時鐘回調。
2. **跨 Module：worker 邊緣的授權 / 速率限制**（→ **TECH-009**，checker 第 1 輪 P2-6）：CORS 白名單目前只決定
   「要不要給瀏覽器讀」，清單外的 Origin 請求仍會被處理；且 `GET /m/:id/wake` 是會改狀態的
   simple GET（可被第三方 `img`/`fetch(no-cors)` 觸發）。M01 範圍只做 CORS 正確性，
   真正的 auth / rate limit 與 `/wake` 改 POST 留待該跨 Module 票處理。
3. **Tauri webview 來源的 CORS 只在瀏覽器驗過**（→ **TECH-006**）：`DEV_ORIGINS` 已列
   `tauri://localhost` / `http://tauri.localhost`，但 E2E 跑的是 `http://localhost:1420`，
   **沒有在真實 webview 內打過一次**。若 webview 的實際 Origin 與假設不同，真機上會以
   「請求根本沒送出」的形式失敗——而那是 M01-US-101 的核心路徑。
   → **已結案**：TECH-006 在打包 app（macOS）與 **iOS 模擬器**內實測皆為
   `origin="tauri://localhost" allowed=true`；iPhone 真機程序已備待用戶。
4. **E2E 用 Desktop Chrome 尺寸**（→ **TECH-007**）：DESIGN 以 iPhone 寬度為準，但 Playwright
   目前只用 `devices["Desktop Chrome"]`，手機寬度的溢出 / 點擊區域未驗。
