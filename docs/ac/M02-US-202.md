## 背景

作為會議參與者，我想 AI 在會議進行中就把逐字稿收好、把承諾抓成待辦，以便會議結束時記錄已經大致成形，而不是結束後才從零開始。

本 US 定義 agent 的能力邊界與工具的重放語意。工具的 `replay` 標記直接關係到 M02-US-201 的 crash recovery 正確性：
不安全的重放會讓「恢復」變成「重複寫入」，因此 AC-1 明示 `append_transcript` 必須是 `replay: "safe"`。

## Given / When / Then

- **Given** 一段逐字稿已產生
  **When** agent 執行寫入
  **Then** 呼叫 `append_transcript` 且該工具註冊為可安全重放（`replay: "safe"`）
  **And** 重放同一呼叫不得產生第二筆相同逐字稿

- **Given** 對話中出現承諾事項（例如「我週五前給你報價」）
  **When** agent 判定為待辦
  **Then** 呼叫 `upsert_action` 寫入待辦，含負責人與期限欄位
  **And** 負責人或期限未提及時欄位為空值（不得猜測填入）
  **And** 同一待辦重複出現時執行更新而非新增第二筆

- **Given** 使用者按下「結束會議」
  **When** 執行 `finalize_notes`
  **Then** 產生三層記錄（逐字稿 / 摘要 / 待辦）
  **And** 已存在的待辦不被覆蓋或清空

## DoD（Definition of Done）

- [ ] 三個工具的 schema 與 `replay` 標記以程式碼固定，並有測試斷言 `replay: "safe"`
- [ ] 待辦去重邏輯有負向探針（重複輸入不得產生兩筆）
- [ ] 「未提及期限 → 空值」以負向探針鎖定（防止模型幻覺填入日期）
- [ ] 系統提示（prompt sections）版本化，並記錄於交付文件
- [ ] `REGRESSION_MODULE=M02` 全綠
