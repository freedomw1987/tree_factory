> 最後更新: 2026-10-07

## 背景

作為會議參與者，我想在會議結束後拿到三層記錄：完整逐字稿、摘要（決策 / 爭點 / 結論）、待辦（誰 / 做什麼 / 何時），
以便我不用重聽錄音就能接續工作。這是整個產品交付價值的最終端點。

AC-2 是刻意的負向要求：**不得幻覺填入日期**。模型很擅長「看起來很合理」地補上期限，
而錯誤的期限比沒有期限更危險（會讓人以為已經約好了）。

## Given / When / Then

- **Given** 一場已結束的會議
  **When** 開啟該場記錄
  **Then** 可看到三層內容：逐字稿（含 speaker 與時間戳）、摘要（決策 / 爭點 / 結論）、待辦（誰 / 做什麼 / 何時）

- **Given** 逐字稿中提及明確的截止日
  **When** 產生待辦
  **Then** 該待辦的期限欄位有值且與逐字稿一致

- **Given** 逐字稿中未提及任何期限
  **When** 產生待辦
  **Then** 期限欄位為空值
  **And** 不得由模型自行填入任何日期

- **Given** 一場 1 小時的會議
  **When** 使用者按下產生記錄
  **Then** 60 秒內完成三層記錄產生

## DoD（Definition of Done）

- [ ] 摘要的三個區塊（決策 / 爭點 / 結論）為固定欄位，未提及時顯示「無」而非空白
- [ ] 「不得幻覺日期」以負向探針鎖定：輸入無期限的逐字稿，斷言期限欄位為空
- [ ] 待辦可回溯至逐字稿原句（與 M02-US-202 的 `upsert_action` 對齊同一識別）
- [ ] 1 小時會議的處理時間有實測數據，並回填 SPIKE-004
- [ ] `REGRESSION_MODULE=M02` 全綠
