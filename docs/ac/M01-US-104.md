# M01-US-104 AC 範本

> 對應 Backlog: [M01-US-104 in docs/backlog.md](../backlog.md)
> Module: M01（聽：收音與即時逐字稿）
> 最後更新: 2026-10-09（v1.4）

## 背景

作為會議參與者，我想在會議進行中就看到逐字稿正在長出來，以便我當下就能確認 AI 真的記下了（而不是結束後才發現整場白錄）。

本 US 對應訪談中的信任感來源：會議中 AI 靜音，所以「看得見」是唯一能讓使用者放心的方式。

## Given / When / Then

- **Given** 有人正在說話且尚未定稿
  **When** 收到 interim 轉譯結果
  **Then** 螢幕顯示未定稿文字
  **And** 未定稿文字在視覺上與已定稿句子可區分（不得同款式）

- **Given** 一段話結束並定稿
  **When** 定稿事件到達
  **Then** interim 文字原地轉為定稿樣式
  **And** 不得同時出現 interim 副本與定稿兩份重複文字

- **Given** 逐字稿已超過一屏
  **When** 有新的定稿句子
  **Then** 畫面自動跟隨至最新一句
  **And** 當使用者手動上滑後停止自動跟隨，直到使用者回到最新處

- **Given** 使用者已停止跟隨且期間有新句子進來（決策 D2）
  **When** 使用者查看畫面
  **Then** 右下角浮動鈕顯示「回到最新 · N 句新」，N 為停止跟隨後新進的句數且會累加
  **And** 點擊後回到底部並恢復跟隨
  **And** 停止跟隨期間新句進來，捲動位置不得跳動（使用者正在讀的那一句不能跑掉）

## DoD（Definition of Done）

- [x] interim 與定稿的字型 / 顏色 / 對齊差異寫入 Design 文件的 §5 樣式表
      （見 [`design/M01-US-104`](../design/M01-US-104-live-transcript-display.md) §5 樣式表：斜體 + 無講者 chip +
      `--text-dim`，**不以顏色為唯一區分**）
- [x] 「使用者手動上滑即停止跟隨」的行為有測試覆蓋（不可只靠肉眼）
      （單元 `live-transcript.test.ts` 的狀態機 + E2E 用 `mouse.wheel(0, -400)` 真的滑，非肉眼）
- [x] 跟隨模式的渲染預算（畫面只留最近 30 句）有探針鎖定，避免長會議全量重繪
      （`RENDER_BUDGET = 30`；單元 M01-DoD ×3 驗「只回 30 + omitted 數字正確」與「interim 不被預算裁掉」）
- [x] 停止跟隨後新句進來時，捲動位置不跳動（以捲動位置斷言，不以肉眼判斷）
      （E2E 斷言寫入前後 `scrollTop` 相等）
- [x] 長逐字稿（≥ 500 句）下捲動不卡頓（量測 fps 或操作延遲）
      — **部分**：E2E 餵 512 句，量到「畫面只渲染 30 列 + 上方省略 482 句」，
      本機桌機 Chromium 一次「捲到頂 → 捲到底 + 強制回流 + 等 2 個 frame」= **17.7~25.3ms**
      （2026-10-09 三次執行：25.3ms、21.3ms、17.7ms；斷言 < 300ms）。
      **未量 fps**，也**未在真機 iPhone 量**；「不卡頓」目前是「DOM 節點有上限 30」＋ 單次操作延遲的證據，
      不是 frame time 的證據。
- [x] `REGRESSION_MODULE=M01` 全綠（`worker/`：`passed=245 failed=0`）

## 誠實聲明（**測不到**的部分，不要讀成已驗證）

1. **真的語音 → interim 事件沒有驗**：裝置端還沒有 STT / nova 接線
   （票已存在但未做：`TECH-003`（P0 / 2SP）與 `INT-M01-M02-01`（P0 / 5SP）），
   interim 由 dev 鉤子 `__tf.pushInterim()` 注入，走的是未來接線**同一條** `applyInterim()` 路徑（單元有覆蓋），
   但「這些字真的來自麥克風」不在本票舉證範圍 → 使用者目前**看不到真的 interim**（見 design §7 風險 1）。
2. **iOS 真機手勢捲動沒有驗**：E2E 是 Chromium 的 `wheel`，不等於手指拖拽；真機手感待 iOS 真機驗收。
3. **未量 fps**：見上面 DoD 最後一條的量測範圍（只量單次操作延遲）。
