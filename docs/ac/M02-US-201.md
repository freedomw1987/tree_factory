## 背景

作為會議參與者，我想在 app 崩潰或 Cloudflare 把物件踢掉之後仍能無縫接回同一場會議，以便逐字稿不會重複、不會斷、不會被計費兩次。

**本 US 是整個 Pi Durable 選型的理由本身**（見 backlog §0.2 SWOT 最終選項）。若本 US 不成立，就沒有必要使用 `PiHarness`，
應退回一般 `Agent` + 自建儲存。因此本 US 的驗收不只是功能，而是「選型是否正確」的驗證。

`PiHarness` 為 Beta，官方明示 API 會變動 → 實作需與 SPIKE-003 的結論一致。

## Given / When / Then

- **Given** 會議已進行到一半且逐字稿已有內容
  **When** app 被強制終止後重新開啟
  **Then** 逐字稿完整還原至中斷前最後一句
  **And** 不需重新送音訊或重新轉譯

- **Given** Durable Object 已被 evict（記憶體中無狀態）
  **When** 新的逐字稿事件到達
  **Then** 物件自動醒回、重開 storage、繼續寫入既有 session
  **And** 不得另開一個新的 session（不得出現兩份逐字稿）

- **Given** 同一段音訊因網路回補被送出兩次
  **When** 伺服端處理第二次
  **Then** 逐字稿只保留一份（冪等）
  **And** 若模型計費以次計，第二次不得產生計費

- **Given** 會議長度超過模型上下文上限
  **When** 持續寫入新的逐字稿
  **Then** 觸發 compaction 後仍可查得會議開頭的內容
  **And** 待辦抽取不受 compaction 影響（會議前段的承諾仍能被抽出）
