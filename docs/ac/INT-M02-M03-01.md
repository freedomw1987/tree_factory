## 背景

作為開發者，我需要 M02（記）與 M03（問）的介面明確，以便單場追問與跨場對話**共用同一套檢索與回答引擎**，
不出現兩套邏輯。

**邊界決定（沿用已批准的 D1 模式「引擎歸一個 Module、UI 入口在另一個」）**：

| 角色 | 歸屬 | 職責 |
| --- | --- | --- |
| 問答引擎（檢索 → 回答 → 附來源） | **M03** | 擁有 |
| 單場追問入口（會議詳情頁的「問這場」+ TTS 出聲） | **M02-US-205** | 呼叫端，傳 `scope = meeting_id` |
| 跨場對話（首頁對話框） | **M03-US-301/303/307** | 呼叫端，傳 `scope = all` |
| 發言者命名資料層（先例） | M01-US-105 | 同一模式（資料層歸 M01，UI 在 M02）|

## Given / When / Then

- **Given** M02 的單場追問被觸發
  **When** 呼叫 M03 引擎
  **Then** 傳入 `scope = meeting_id`，M03 的所有回答都限定在該場
  **And** 來源回溯一律落在該場逐字稿

- **Given** 同一份 M03 引擎
  **When** 由首頁對話框呼叫（`scope = all`）
  **Then** 檢索跨場並逐條附來源，M02 不需實作任何檢索邏輯

- **Given** 引擎回答引用的句子已被人工編輯（決策 D8）
  **When** 任一呼叫端顯示該來源
  **Then** 兩個呼叫端都必須顯示「此句有人工修正」（標示責任在引擎，不在呼叫端）

## DoD（Definition of Done）

- [ ] M03 引擎以明確參數 `scope` 受理，不靠 prompt 提示範圍
- [ ] 探針證明：M02 端不含任何檢索 / 排序 / 去重邏輯（只有呼叫與顯示）
- [ ] 兩個呼叫端顯示的來源格式一致（同一 renderer）
- [ ] `M02-US-205` 的描述已改為「單場範圍的呼叫端」（見 backlog v2.0）
- [ ] 人工修正標示由引擎提供，呼叫端不得自行判斷
