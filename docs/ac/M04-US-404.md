# M04-US-404 AC 範本

> 對應 Backlog: [M04-US-404 in docs/backlog.md](../backlog.md)

> 最後更新: 2026-10-07

## 背景

作為使用者，我想會議記錄像 wiki 一樣有「概念」可以瀏覽，以便 agent 與我都能更快理解累積的知識。

**這是最後一階段（Phase C）的能力**，依賴前兩階段累積的資料量；資料太少時概念層沒有價值。

AC-4 是誠實條款：概念是**機器抽取**的產物，必然有錯。必須明說並提供修正入口，
不得讓使用者以為概念層是「已確認的知識」。

## Given / When / Then

- **Given** 一場會議已產生三層記錄
  **When** 執行概念提取
  **Then** 抽出概念（人名 / 專案 / 決策主題 / 關鍵名詞）並為每個概念建立概念卡

- **Given** 一張概念卡
  **When** 檢視它
  **Then** 可回溯到產生它的來源句（含會議、時間、發言者）

- **Given** 概念卡有錯（誤抽、重複、命名不佳）
  **When** 使用者編輯
  **Then** 可改名、合併、刪除；且修正後的結果被後續提取沿用（不得每次重新抽到同一個錯）

- **Given** 概念為機器抽取
  **When** 使用者首次看到概念層
  **Then** 明說「概念由 AI 抽取，可能有誤，可手動修正」
  **And** 每個概念卡都有修正入口

## DoD（Definition of Done）

- [ ] 概念抽取可回溯來源句（與 M03-US-302 同一契約）
- [ ] 使用者修正（改名/合併/刪除）會被持久化並影響下一次提取
- [ ] 抽取失敗不得影響會議記錄本身（記錄仍可讀）
- [ ] 成本與品質以 SPIKE-006 實測數據為準，非猜測
- [ ] 探針 `REGRESSION_MODULE=M04` 全綠
