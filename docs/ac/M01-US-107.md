# M01-US-107 AC 範本

> 對應 Backlog: [M01-US-107 in docs/backlog.md](../backlog.md)
> Module: M01（聽：收音與即時逐字稿）
> 最後更新: 2026-10-09

## 背景

作為會議參與者，我想在錄音被系統中斷時（切到背景、鎖屏）**留下明確的缺口記號**，
以便我日後看逐字稿時不會把「沒錄到」誤讀成「當時沒人說話」。

失敗模式 F22 的原形是「靜默缺段」：畫面回到前台、看起來一切正常，但中間那 3 分鐘的音檔與逐字稿
根本不存在。這一票的核心不是「把音補回來」（那是 US-106 原生層），而是**誠實標記**：
缺口要看得見、要有時間範圍，而且同一次中斷只能標一次（否則逐字稿會被重複的「未錄到」噪音淹沒）。

## Given / When / Then

- **Given** 會議正在錄音
  **When** app 被切到背景或鎖屏（`visibilitychange → hidden`）
  **Then** **當下**即在本機與伺服端寫入一筆 `TRANSCRIPT_GAP`（含開始時間）
  **And** 不得等到回到前台才寫（被系統殺掉就永遠不知道有缺口）

- **Given** 已有一筆缺口記號
  **When** 使用者回到前台並看逐字稿
  **Then** 缺口處顯示「此段未錄到」與時間範圍（含中斷期間長度）
  **And** 尚未關閉的缺口要明說「結束時間未知」，不得假裝範圍已知

- **Given** 同一次中斷（中間沒有成功續錄）
  **When** `hidden` 事件重複觸發（iOS webview 會重複送）
  **Then** 只保留一筆缺口、seq 不得遞增、逐字稿不得出現第二列
  **And** 續錄後再次中斷 → 這是**新的一筆**（不同 seq），必須各自標記

## DoD（Definition of Done）

- [x] 缺口記號在**離線時也不丟**（本機先落地，連線恢復後補送；被殺掉後重開仍在）
- [x] 缺口時間範圍以**伺服端權威時間軸**為準（裝置端 elapsed 由 `session.startedAtMs` 推導；長度讀 `wallClockElapsedMs`，D10）
- [x] 探針含正向（中斷 → 逐字稿出現缺口）與負向（同段重複 hidden 不得產生第二筆）兩類斷言
- [x] 伺服端拒絕不合法範圍（`toMs < fromMs`、`fromMs < 0`、範圍起點超過已過時間）
- [x] `REGRESSION_MODULE=M01` 全綠

## 範圍外（明確不做，避免膨脹）

- **把音補回來**：US-106 原生錄音層（本票只標記，不假裝能補）。
- **逐字稿文字本身**：US-103 / US-104（本票只引入「缺口列」，文字列由它們接上）。
- **多場會議同時缺口的 UI 彙總**：M02。
